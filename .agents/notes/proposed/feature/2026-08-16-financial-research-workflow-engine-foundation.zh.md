# Agent Note: Financial research workflow-engine foundation

Status: proposed

[English](2026-08-16-financial-research-workflow-engine-foundation.md) | 中文

## Problem

DeepSeek Harness 已经具备构建工作流优先研究系统所需的核心能力缝，但仓库里还没有一份面向金融场景的具体设计，来固定第一交付物、执行边界和这种组合方式的验收标准。

如果没有这份设计，后续实现很容易同时铺开研究工作台、数据接入、专责智能体和编排能力。

这会让第一阶段范围过大，模糊 `workflow`、`subagent`、`tools` 和 `session` 之间的职责划分，也削弱仓库对一个聚焦 assembled example 的证明能力。

## Proposal

把第一份面向金融场景的交付物定义为一个工作流优先的多智能体研究引擎，服务于小型团队，部署在本地或内网环境，基于公开数据运行。

第一阶段围绕一条标准混合研究模板展开：接收任务、采集公开证据、委派有界专责分析、汇总产物，并产出带有可回放轨迹的报告草稿。

`workflow` 负责编排和节点生命周期。

`subagent` 负责专责执行单元。

`tools` 负责数据获取、标准化、计算和规则检查。

`session` 负责回放、可观测和后续工作台视图所依赖的持久化轨迹。

产品壳层、私有数据接入、企业级权限和广义模板管理都不属于这一阶段范围。

详细设计写在[配对规格文档](../../../../docs/superpowers/specs/2026-08-16-financial-research-workflow-engine-design.md)里。

## Expected composition

第一阶段的节点类型应保持精简：入口、工具、委派、汇总和产出。

一条标准混合研究流程至少应支持财报解析、新闻归因、估值分析和风险审阅这几类专责任务。

最小可见面应该展示任务树、节点状态、失败或重试原因，以及能分开查看证据包和报告草稿的产物视图。

## Alternatives considered

**先做完整研究工作台。** 不采纳，因为最有价值的早期证明是执行可靠和过程可观测。过早扩大 UI 壳层，会在执行内核稳定前提前锁死产品布局、协作交互和状态归属。

**先做金融技能中心。** 不采纳，因为孤立的工具无法证明任务拆解、并行执行和结果汇总。仓库已有较强的工具能力缝，真正缺的是 assembled workflow 的第一份证明。

**先做平台级任务中台。** 第一阶段不采纳，因为它会在一条端到端研究流程尚未成立之前，就提前为更大产品形态优化。工作流优先的设计让第一步更可演示，也更有边界。

## Acceptance criteria

- 这份设计把第一阶段固定为工作流优先的金融研究引擎，而不是整个平台的一次性建设。
- 这个阶段明确限定在本地或内网部署、公开数据和一条标准混合研究模板之内。
- `workflow`、`subagent`、`tools` 和 `session` 之间的职责划分足够清晰，能够指导后续实现。
- 配对规格文档定义了实现规划所需的节点模型、执行流程、可观测要求和验证路径。

## Risks

即使范围已经收窄，第一阶段仍可能被过早要求补上更完整的 UI、更多模板或私有数据接入。

因此，这个提案成立的前提，是把第一阶段的验收标准始终锁定在执行质量和留痕能力上，而不是广度。

只使用公开数据也会限制部分金融团队的现实适配度，但这个取舍让第一份 assembled example 可以在不依赖外部系统的情况下落地实现。
