多智能体工作流引擎：系统架构与模块边界

方案 A：以 Workflow 为中心，Subagent 作为执行单元，Skill 作为能力底座，Session 负责留痕与回放

设计目标

先把研究任务拆解、编排、执行、观测、留痕这一条主链路做扎实，再让研究工作台和金融技能中心以插件方式挂载进来。

核心模块关系

研究入口

对话工作台 / API / 批量任务入口

Workflow Orchestrator

任务模板、步骤依赖、状态机、重试、终止、结果汇总

Session / Audit

过程日志、子任务轨迹、中间结果、最终产物回放

Subagent Pool

财报解析、新闻归因、估值分析、风险审阅、报告撰写

Skill / Tool Layer

公开数据抓取、结构化提取、指标计算、报告导出、规则校验

结果输出

研究结论、标准化报告、任务树视图、阶段日志

主数据流

1. 发起任务

研究员在工作台提交一个研究主题或批量任务，选择模板与输出目标。

2. 编排拆解

Workflow 把任务拆成节点，决定哪些节点走 tool，哪些节点派给 subagent。

3. 并行执行

子智能体各自调用技能层处理公开数据、分析、校验与写作。

4. 汇总留痕

节点状态、日志、中间结果和最终产物统一进入 Session 体系，供工作台展示与回放。

边界原则

明确归属

  • 流程控制归 Workflow
  • 专业分工归 Subagent
  • 外部能力归 Skill / Tool
  • 审计回放归 Session

刻意避免

  • 让 Subagent 直接承担全局编排
  • 让 Tool 层偷偷承载业务流程
  • 把工作台状态和执行状态耦死
  • 把最终报告生成散落在多个节点里
