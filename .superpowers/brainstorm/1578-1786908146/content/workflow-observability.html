第一阶段不追求复杂调度，但必须做到：状态清晰、失败可控、过程可见、结果可回放

工作流状态机
Workflow Run 生命周期

Created

任务创建，模板与输入就绪

Planning

节点图展开，依赖与路由确定

Running

工具节点与委派节点按依赖执行

Completed

全部必要产物已生成并收口

Failed

关键节点失败且无法自动恢复

Cancelled

用户或系统主动终止执行

节点状态机

Pending

等待上游依赖完成，尚未开始执行。

Ready

依赖已满足，可进入执行队列。

Running

工具调用或子智能体任务正在进行。

Succeeded / Failed / Skipped

节点有明确结局，并带着结构化结果或错误原因结束。

失败恢复策略

第一阶段建议支持

  • 工具节点有限次自动重试
  • 委派节点失败后回传结构化错误
  • 非关键节点可标记降级继续
  • 最终报告明确缺失证据与失败步骤

第一阶段不做

  • 任意节点从中间精确断点恢复
  • 复杂人工介入编排
  • 跨多天的长时作业恢复
  • 自动改写工作流图再执行
工作台需要看到什么
最小可观测视图

任务树

展示 Workflow Run、节点依赖、当前阶段、节点负责人 Agent。

阶段日志

每个节点的开始、结束、重试、失败原因与关键产物摘要。

产物面板

证据包、风险清单、报告草稿、最终结论都能单独查看。

与 DeepSeek Harness 的映射

Workflow 事件

承接工作流运行状态与节点生命周期，是工作台进度视图的主来源。

Subagent Report

承接委派节点的中间进展与完成结果，适合填充任务树子分支。

Session Log

承接全链路留痕，保证模型可见内容与工作台可回放内容一致。
