多智能体工作流引擎：任务模型与节点类型

目标是把“混合研究”拆成稳定、可并行、可回放的节点，而不是让一个 Agent 从头做到尾

任务模型

研究任务 Research Job

一次完整研究请求。包含主题、范围、输出目标、优先级、触发方式、执行模板。

工作流实例 Workflow Run

某个模板在本次任务上的真实执行。包含节点图、状态、依赖、时间线与终止原因。

节点执行 Node Run

单个步骤的一次运行记录。可由 Tool 直接执行，也可委派给 Subagent。

研究产物 Artifact

结构化中间结果与最终成果，如资料包、估值摘要、风险清单、最终报告。

建议的第一阶段节点图

1. 任务初始化

校验输入、选择模板、写入 Session、生成任务上下文

2. 资料采集

公开数据抓取、新闻与财报获取、基础结构化清洗

3. 路由拆解

根据任务类型拆给财报、行业、量化、风险等子任务

4. 结果汇总

合并中间结论、生成统一证据包、形成后续写作上下文

5. 并行分析节点

财报解析 Agent、新闻归因 Agent、估值 Agent、风控审阅 Agent 可并行执行

6. 报告生成节点

基于统一证据包输出研究结论、报告草稿与关键风险提示

7. 结束与回放

产物入库、状态收口、任务树与日志可供工作台查看

第一阶段节点类型

建议保留的 5 类节点

  • 入口节点：初始化任务、装载上下文
  • 工具节点：调用公开数据与基础分析能力
  • 委派节点：把专门任务交给子智能体
  • 汇总节点：合并结构化结果，判断缺口
  • 产出节点：生成研究结论、报告与任务摘要

第一阶段暂不引入

  • 过于细碎的十几种节点 DSL
  • 复杂人工审批节点
  • 跨工作流嵌套调用
  • 长时调度和定时批处理编排
一个典型混合研究任务
示例：研究“某公司在行业周期中的投资价值”

初始化任务

-> 采集公开资料

-> 并行分发给财报解析 / 行业景气分析 / 新闻归因 / 风险审阅

-> 汇总统一证据包

-> 生成研究结论与报告草稿

-> 写入会话与任务树供工作台回放
